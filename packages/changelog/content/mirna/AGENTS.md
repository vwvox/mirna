# Mirna release notes

One file per release, named after the version (`0.1.0-beta.4.md`). The Mac
app bundles every file here and shows them newest first on its What's new
page; the release workflow puts the release's own file in its GitHub notes.

- Write for people using Mirna: what they can do now, what works better,
  what got fixed. Leave out internal changes, CI and refactors.
- Short, plain sentences in the app's calm tone. Name places in the app the
  way they read ("Settings › Phone").
- Frontmatter needs `date` ("YYYY-MM-DD", the day the tag was pushed) and
  `summary` (one plain sentence, no Markdown), shown as the release's lead.
- Changes to the Android app go under `## On your phone`, with its version.
